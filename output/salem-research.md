# Salem 1692 线上桌游 -- 研究报告

> Super Dev | Phase: research [1/9] | 2026-05-15

---

## 一、产品定义

**目标**: 在火山引擎 ECS (115.190.232.225) 上部署 Salem 1692 的手机端 Web 桌游，通过浏览器直接访问，无需下载。

**核心玩法**: 4-12 人社交推理卡牌游戏，玩家通过指控、辩护、投票揭露女巫，或作为女巫消灭镇民。

---

## 二、游戏规则摘要

完整规则见 `knowledge/salem-1692-rules.md`（670 行）。

### 核心机制
- **审判卡系统**: 每人 3-5 张面朝下的审判卡（女巫/非女巫/警长）
- **塞勒姆牌组**: 红(指控)/绿(行动)/蓝(持续)/黑(事件) 四色卡牌
- **白天回合**: 二选一 -- 出牌(至少1张) 或 抽牌(2张)
- **指控审判**: 累计 7 点指控触发翻卡
- **夜间阶段**: 牌堆耗尽触发 -> 女巫杀人 -> 警长保护 -> 认罪窗口(30秒)
- **胜利条件**: 镇民翻出所有女巫卡 / 女巫杀光所有非女巫
- **阴谋卡**: 审判卡左传，可能导致阵营变动

### 卡牌分配（按人数）
| 人数 | 4 | 5 | 6 | 7 | 8 | 9 | 10 | 11 | 12 |
|------|---|---|---|---|---|---|----|----|-----|
| 女巫 | 1 | 1 | 2 | 2 | 2 | 2 | 2  | 2  | 2   |
| 警长 | 1 | 1 | 1 | 1 | 1 | 1 | 1  | 1  | 1   |
| 每人卡数 | 5 | 5 | 5 | 5 | 4 | 4 | 3 | 3 | 3 |

### MVP 范围决策
- **包含**: 基础规则（标准版卡牌 + 基础角色能力）
- **不包含**: 豪华版特殊审判卡、先令系统、2-3 人变体
- **角色**: MVP 阶段先实现 8 个已确认能力的角色，其余标记为"无特殊能力"

## 三、竞品分析

| 产品 | 类型 | 技术栈 | 特点 |
|------|------|--------|------|
| Town of Salem | PC/主机 | Unity | 700万+用户，重客户端 |
| Wolvesville | 移动端 | 原生App | 100+角色，跨平台 |
| play-werewolf.app | Web | Node+Socket.IO+Redis | 免注册，房间码 |
| Tabletopia (Salem) | Web | 专用引擎 | 通用桌游模拟器，非定制 |

**关键洞察**:
1. 社交推理游戏核心技术门槛不高，主要挑战是状态同步和信息隔离
2. 所有成功产品都使用 WebSocket
3. 免注册 + 房间码是 Web 端标准模式

## 四、技术方案

### 4.1 推荐技术栈

| 层级 | 选型 | 理由 |
|------|------|------|
| 游戏框架 | **Colyseus 0.16** | 回合制卡牌游戏的完美框架，内置房间/状态同步/断线重连/信息隔离 |
| 前端 | **React 19 + Vite + TypeScript** | Colyseus 一等支持，组件化管理复杂 UI |
| 样式 | **TailwindCSS** | 移动端自适应，utility-first |
| 图标 | **Lucide React** | 轻量专业 |
| 动画 | **Framer Motion** | 卡牌翻转、投票等动画 |
| 进程管理 | **PM2** | 行业标准 |
| 反向代理 | **Nginx** | WebSocket 代理 |
| 语音(MVP) | **不做** | 文字聊天足够，语音占 30-40% 工作量 |

### 4.2 为什么选 Colyseus 而不是 Socket.IO

Colyseus 开箱即用的功能：
- 房间管理（创建/加入/锁定/自动清理）
- `@colyseus/schema` 增量二进制序列化（只同步变化字段）
- `@filterChildren` 实现信息隔离（手牌对他人不可见）
- 60 秒断线重连窗口
- TypeScript 前后端类型共享

用 Socket.IO 需要自己实现以上所有功能。

### 4.3 架构图

```
[手机浏览器] <--HTTP/WS--> [Nginx :18790] <--proxy--> [Colyseus :2567]
                                                       [PM2 管理]
                           前端静态资源由 Nginx 直接托管
```

端口 18790 避免与 OpenClaw(18789) 冲突。

### 4.4 域名问题

当前方案：IP 直接访问（http://115.190.232.225:18790）
- 优势：零成本，立即可用
- 限制：无 HTTPS，无法使用 Service Worker / Web Push
- 对游戏功能无影响

### 4.5 语音方案（后续扩展）

| 方案 | 适用人数 | 复杂度 |
|------|----------|--------|
| PeerJS (P2P Mesh) | 4-6人 | 低 |
| LiveKit (SFU 自托管) | 4-100+ | 中 |

MVP 不做语音，用文字聊天替代。

## 五、核心状态机

```
LOBBY (等待玩家)
  -> DAWN (黎明: 女巫放黑猫)
    -> DAY_TURN (白天回合: 出牌/抽牌)
      -> [出牌 -> 检查指控 -> 可能触发审判]
      -> [抽牌 -> 可能抽到黑色卡牌]
        -> [阴谋: 审判卡左传]
        -> [黑夜: 进入夜间]
    -> NIGHT_WITCH (女巫选目标)
      -> NIGHT_CONSTABLE (警长选保护)
        -> NIGHT_CONFESS (30秒认罪窗口)
          -> NIGHT_RESOLVE (结算击杀)
            -> CHECK_WIN (检查胜负)
              -> DAY_TURN 或 GAME_OVER
```

## 六、前端页面规划

| 页面 | 功能 |
|------|------|
| 首页 | 创建房间 / 输入房间码加入 |

- 竖屏优先
- 触摸目标最小 44x44px
- 手牌底部扇形展开
- 玩家头像圆形围坐
- safe-area-inset 适配刘海屏

## 八、部署与运维

- 服务器: 火山引擎 ECS, Ubuntu 24.04, 8GB RAM
- 与 OpenClaw(18789) 和 IdeaMatrix(8800) 共存
- Colyseus 单进程约 100MB，每房间约 2MB
- 8GB RAM 可承载 100+ 并发房间
- PM2 管理进程，开机自启
- Git 部署: commit -> push -> pull -> pm2 restart
