# Proposal: Playable Card Assets And Real E2E Validation

## 背景

Claude Code 已完成 Salem 1692 在线桌游的一部分前后端实现，但卡牌实物图片获取和处理未闭环。当前前端已有一批 `packages/client/src/assets/cards/*` 图片，但未接入真实卡牌 UI，且图片命名是抓取序号，缺少与 `CardType` / `TryalCardType` 的稳定映射。

## 目标

- 将现有可用实物卡牌图片接入前端卡牌渲染。
- 对缺失素材提供同风格可玩降级卡面，避免继续卡死在图片抓取。
- 修复阻碍真实多人游戏的前后端问题。
- 启动本地服务并执行多玩家端到端测试，覆盖真实页面点击和语音链路连接检查。

## 非目标

- 不继续从未知来源批量抓取完整商业卡牌素材。
- 不在没有完整授权素材的情况下阻塞可玩性。
- 不执行生产服务器变更、数据库写入或 Nginx/systemd/firewall 修改。

## 验收标准

- `GameCard` 能优先展示已映射实物卡图。
- 缺图卡牌仍以统一视觉可读卡面渲染。
- 前后端 build 通过。
- 本地 server/client 可启动。
- 至少 4 个模拟玩家可通过浏览器端到端完成创建/加入/准备/开始和若干轮真实交互。
- 语音链路至少验证 token/API/前端权限与连接路径，不因缺本地 LiveKit 服务导致整个游戏 E2E 失败。
